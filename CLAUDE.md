# PaveDetail - детали модуля

> Чертежи узлов дорожной одежды по регионам площадки Robur: разрез со штриховками
> по материалам, номера слоёв цифрами у грани, экспликация справа, ведомость состава.
> Оформление повторяет табличный эталон заказчика - выносок нет.

**Версия:** 1.0.0 | **Сборка:** Debug | **LangVersion:** latest | **Статус:** 🚧 разработка (таблица вставляется в план/Чертёж и запоминает ввод, каталог гридом - живьём подтверждено 2026-09-08; графы каталога и текст ведомости поправлены следом, окно каталога теперь само шире графов - живой гейт не переоткрывался)
**Артефакт:** `PaveDetail-1.0.0.tpm`

## Зарегистрированные команды

| Команда | Описание |
|---------|---------|
| `pavedetail_node` | Узел по одному региону площадки |
| `pavedetail_batch` | Узлы по всем уникальным конструкциям площадки |
| `pavedetail_report` | Ведомость состава конструкций на план |
| `pavedetail_table` | Сводная таблица «Детали покрытий» по всей площадке |
| `pavedetail_export` | Выгрузка таблицы или ведомости в CSV/HTML |
| `pavedetail_catalog` | Правка каталогов материалов и бортов |
| `about_pavedetail` | Диалог «О модуле» |

## Архитектура

- `Core/` - чистое ядро без ссылок на Topomatic, покрыто xunit (`Tests/PaveDetail.Tests`, 84 теста).
  `NodeBuilder` строит `Shape`-список в метрах: верх покрытия на Y = 0, слои уходят в минус.
- `Cad/SiteReader.cs` - единственное место чтения площадки. В Robur ДВА независимых
  источника слоёв дорожной одежды (оба - строка формата `Topomatic.Sites.MaterialsLayers`):
  модификатор **«Слои ДО»** пишет в семантику слоя `SitePavement` (`BasePatch == Region.Patch`)
  кодами классификатора (`SmdxGenplanSmallAsphalt`), поле **«Контроллер КДО»** в семантике
  самого региона - готовым русским текстом. `SiteReader` ищет строку по содержимому
  (регэксп), а не по конкретному тегу - теги нестабильны между источниками. Подробности
  и живые данные разведки - `docs/api-notes.md`.
- `Core/SmdxClassifier.cs` + `Cad/SmdxClassifierLocator.cs` - код классификатора → русское
  имя, файл `%ProgramData%\Topomatic\{Продукт}\{Версия}\Support\Smdx\materials.smdx`.
  Для готового текста (из «Контроллера КДО») работает как passthrough.
- `Cad/DrawingWriter.cs` - единственное место записи в чертёж. Слои `PD_HATCH`,
  `PD_LINE`, `PD_TEXT`, всё в одной транзакции. Слоя `PD_LEADER` больше нет:
  выноски убраны 2026-08-28 по эталону заказчика.
- Каталоги `Catalog/materials.json` и `Catalog/borders.json` - ресурс в сборке,
  копия в `%AppData%\ABR\PaveDetail`, дальше правит пользователь. Правка - гридом
  в `Ui/CatalogDialog.cs` (образец штриховки рисует `Ui/HatchPreview.cs`), обратная
  сборка в JSON - `Core/CatalogJson.cs`. Формат файла тот же, что был: его
  по-прежнему можно править руками через «Открыть папку».
- `Core/TableBuilder.cs` + `Core/TableModel.cs` - лист «Детали покрытий»: сетка линиями
  и текст, мини-разрез в ячейке строит `Core/CompactSection.cs`. Графы, которых нет
  в модели (шифр, раздел, модуль упругости, примечание), лежат в `<проект>.pavedetail.json`
  рядом с `.rbprojx` (`Cad/ProjectPaths.cs`) и правятся в `Ui/TableDialog.cs`.

## Известные упрощения v1

- Узел - снапшот примитивами, живой связи с регионом нет: правил слои - строй заново.
- Размерных примитивов нет, толщины подписаны только в экспликации.
- Вертикального преувеличения нет.
- Лист А4 со штампом отложен в v2, узел кладётся в модель по указанной точке.
- Штриховки по именам `ANSI31`/`GRAVEL`/`AR-SAND`/`AR-CONC`/`EARTH`; при промахе
  правила - `SOLID` с цветом слоя из модели.
- Борт (`SiteBorder`) - гипотеза о совпадении `BaseLine` с регионом НЕ подтверждена
  живьём (юзер ни разу не задавал борт в тестовом проекте); закрывается в Task 14.
